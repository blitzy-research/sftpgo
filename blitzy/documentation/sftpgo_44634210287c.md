# SFTPGo `0.9.5-dev` — Runtime-Observed Investigation: Concurrency, Quota Enforcement, and Atomic Uploads Under a Contended Burst

> **Scope & method.** This document answers, *from observed runtime behavior*, how SFTPGo's connection handling, quota enforcement, and atomic-upload mechanisms coordinate when one strictly quota-limited user drives concurrent uploads across multiple near-`max_sessions` sessions while the background idle checker runs. Every behavioral claim is paired with the concrete captured output that demonstrates it, together with the exact command that produced it. Statements derived from reading code but **not** exercised at runtime are explicitly marked **`[inferred]`**. Findings are specific to the checked-out revision and are **not** generalized.
>
> - **Target:** `github.com/drakkan/sftpgo`, source branch `sftpgo_44634210287c`, baseline HEAD `44634210287cb192f2a53147eafb84a33a96826b`, version string `0.9.5-dev` (`go.mod`: `go 1.13`).
> - **Build toolchain:** `go version go1.13.15 linux/amd64`; CGO enabled (gcc) for the `mattn/go-sqlite3` driver.
> - **Data provider:** SQLite (`cache=shared`, single writer), `track_quota: 2`.
> - **Entry point exercised:** a real SFTP client over the wire (`github.com/pkg/sftp` v1.11.0 + `golang.org/x/crypto/ssh`) into the running server at `127.0.0.1:2022` — the canonical path (SSH auth callback → `loginUser` → `handleSftpConnection` → SFTP file handlers). No bypassing/synthetic interface produced any reported value.
> - **Read-only:** no repository source file was modified; the only repository artifact produced is this document. All harness/config/db/log artifacts lived under `/tmp/sftpgo_work` (outside the checkout) and were removed after the investigation (§6).
> - **Reproducibility note.** Volatile values differ run to run and therefore differ from any prior write-up: connection-id hashes, the `xid` GUID embedded in each temp-file name, ephemeral client ports, wall-clock timestamps, and — because two check-then-act races are under study — the number of admitted sessions and the resulting quota. Every value below is the *actual* value captured in the run shown; re-running reproduces the *structure* and the invariants, not the exact hashes/ports/timestamps.

## TL;DR — direct answers

- **O1 (burst under strict limits).** Under a *truly simultaneous* burst, **both** the `max_sessions` cap **and** the quota limits are raced through with **zero** rejections logged for the racing transfers. Sessions admitted against `max_sessions=3` ranged over **{3, 4, 5, 6}** across repeated identical runs (peak **6** open connections observed). Driving six 700-byte uploads at a `quota_files=3` / `quota_size=3000` user, the user's stored quota ended **over the file limit in 19 of 24 runs**, **over the size limit in 17 of 24 runs**, **over both in 17 of 24**, and **over at least one in 19 of 24** (§3.7). When connections are even slightly staggered, the session cap holds cleanly (**3 accepted / 3 refused**, deterministic — §3.6).
- **O2 (race vs. serialize).** Quota **accounting serializes** (an atomic relative SQL increment on a single-writer SQLite connection — *no lost updates in any of 24 runs*); quota **enforcement races** (a time-of-check/time-of-use gap). The Go **data-race detector reported no data race** (empty stderr on the `-race` build across the burst). The overshoot is therefore a **logical TOCTOU race**, not a memory data race. It **first manifests** as the final `used_quota_*` exceeding the configured limit with **no** `quota exceed` log emitted during the burst (§3.2).
- **O3 (partial atomic temp file on a dropped transfer).** In atomic mode (`upload_mode: 1`) the partial temp file `.sftpgo-upload.<xid>.<name>` is **deleted** and **no quota is ever added** (reversal-by-never-applying). In atomic-with-resume (`2`) the partial temp is **renamed to the target** and its bytes **are counted** — a partial target lingers by design. In standard mode (`0`, the shipped default) there is no temp file — a **partial target** is left and its bytes **are counted** (§3.4).
- **O4 (observable evidence).** Captured per condition below, each with its producing command: accepted/refused session tallies plus the verbatim `too many open sessions` log; the step-by-step `used_quota_files`/`used_quota_size` progression from SQLite; and the presence/absence of `.sftpgo-upload.*` temp files on the filesystem (§3).
- **O5 (kill mid-stream vs. normal completion).** Distinguished by the temp-file disposition (rename vs. delete) and the log signatures — a clean completion logs `atomic upload completed, rename: … error: <nil>` with **no** `transfer error`; a kill logs `transfer error: EOF` and, in atomic mode, `atomic upload completed with error: … delete temporary file` (§3.4, table in §3.4).
- **O6 (coordination/handoffs).** A single package-level `sync.RWMutex` guards the `openConnections`/`activeTransfers` registries; admission is decided at auth time (before registry insertion) and the quota **limit** is checked at file-open (before the completion-time commit) — two check-then-act handoffs with no spanning transaction, which is why a clean run and a contended run diverge (§2, §3.7).

### 1.8 The SFTP client harness (complete source)

The harness is the real SFTP client used for every session below. It lives at `$WORK/harness/main.go` in its own module (`module sftpobs`, `go 1.13`, requiring `github.com/pkg/sftp v1.11.0` and the repo's `golang.org/x/crypto` version; the repository `go.sum` is reused for offline checksums), and is built with `GOPROXY=off go build -o $WORK/harness/harness .`. It is removed at the end (§6). Full source:

```go
// Temporary observation harness for the SFTPGo runtime investigation.
// Drives the canonical entry point: a real SFTP client over the wire
// (github.com/pkg/sftp + golang.org/x/crypto/ssh) into the running server.
// This file lives under /tmp (outside the repository checkout) and is removed
// after the investigation; it is NOT part of the repository.
package main

import (
	"flag"
	"fmt"
	"net"
	"sync"
	"sync/atomic"
	"time"

	"github.com/pkg/sftp"
	"golang.org/x/crypto/ssh"
)

var (
	mode    = flag.String("mode", "upload", "upload|seq|burst|kill|hold|idlehold")
	addr    = flag.String("addr", "127.0.0.1:2022", "server address")
	user    = flag.String("user", "qtest", "username")
	pass    = flag.String("pass", "qtestpass", "password")
	remote  = flag.String("remote", "f.txt", "remote file name (upload/kill/idlehold)")
	names   = flag.String("names", "", "comma-separated remote names (seq)")
	size    = flag.Int("size", 500, "bytes to write")
	count   = flag.Int("count", 6, "number of concurrent goroutines (burst/hold)")
	stagger = flag.Int("stagger", 0, "ms between connection starts (hold)")
	hold    = flag.Int("hold", 6, "seconds to hold a connection open (hold)")
	prefix  = flag.String("prefix", "burst_", "remote name prefix (burst)")
	idle    = flag.Int("idle", 330, "seconds to hold idle before closing (idlehold)")
)

func clientConfig() *ssh.ClientConfig {
	return &ssh.ClientConfig{
		User:            *user,
		Auth:            []ssh.AuthMethod{ssh.Password(*pass)},
		HostKeyCallback: ssh.InsecureIgnoreHostKey(),
		Timeout:         15 * time.Second,
	}
}

// dialRaw returns the raw net.Conn plus a live sftp client so callers can drop
// the TCP connection abruptly (net.Conn.Close) to simulate a mid-stream kill.
func dialRaw() (net.Conn, *ssh.Client, *sftp.Client, error) {
	nc, err := net.DialTimeout("tcp", *addr, 15*time.Second)
	if err != nil {
		return nil, nil, nil, err
	}
	sc, chans, reqs, err := ssh.NewClientConn(nc, *addr, clientConfig())
	if err != nil {
		nc.Close()
		return nil, nil, nil, err
	}
	cli := ssh.NewClient(sc, chans, reqs)
	sf, err := sftp.NewClient(cli)
	if err != nil {
		cli.Close()
		nc.Close()
		return nil, nil, nil, err
	}
	return nc, cli, sf, nil
}

func payload(n int) []byte {
	b := make([]byte, n)
	for i := range b {
		b[i] = byte('A' + (i % 26))
	}
	return b
}

func doUpload(remoteName string, n int) error {
	_, cli, sf, err := dialRaw()
	if err != nil {
		return fmt.Errorf("connect: %v", err)
	}
	defer cli.Close()
	defer sf.Close()
	f, err := sf.Create(remoteName)
	if err != nil {
		return fmt.Errorf("create: %v", err)
	}
	if _, err := f.Write(payload(n)); err != nil {
		return fmt.Errorf("write: %v", err)
	}
	if err := f.Close(); err != nil {
		return fmt.Errorf("close: %v", err)
	}
	return nil
}

func main() {
	flag.Parse()
	switch *mode {
	case "upload":
		if err := doUpload(*remote, *size); err != nil {
			fmt.Printf("UPLOAD result=ERROR err=%v\n", err)
		} else {
			fmt.Printf("UPLOAD result=OK remote=%s size=%d\n", *remote, *size)
		}

	case "seq":
		for _, nm := range splitCSV(*names) {
			if err := doUpload(nm, *size); err != nil {
				fmt.Printf("SEQ %s ERROR %v\n", nm, err)
			} else {
				fmt.Printf("SEQ %s OK size=%d\n", nm, *size)
			}
		}

	case "burst":
		// Client-side barrier: every goroutine calls Create() (server hasSpace at
		// open) and only AFTER all have done so are writes+closes released. This
		// guarantees all quota checks read committed state before any commit.
		var createdOK, createDenied, closedOK int64
		var ready sync.WaitGroup
		release := make(chan struct{})
		ready.Add(*count)
		var wg sync.WaitGroup
		wg.Add(*count)
		for i := 0; i < *count; i++ {
			go func(idx int) {
				defer wg.Done()
				nc, cli, sf, err := dialRaw()
				if err != nil {
					fmt.Printf("g%02d CONNECT-ERR %v\n", idx, err)
					ready.Done()
					return
				}
				defer cli.Close()
				defer nc.Close()
				f, err := sf.Create(fmt.Sprintf("%s%d", *prefix, idx))
				if err != nil {
					atomic.AddInt64(&createDenied, 1)
					fmt.Printf("g%02d CREATE-DENIED %v\n", idx, err)
					ready.Done()
					return
				}
				atomic.AddInt64(&createdOK, 1)
				ready.Done()
				<-release // barrier: wait until all goroutines have created
				if _, err := f.Write(payload(*size)); err != nil {
					fmt.Printf("g%02d WRITE-ERR %v\n", idx, err)
					return
				}
				if err := f.Close(); err != nil {
					fmt.Printf("g%02d CLOSE-ERR %v\n", idx, err)
					return
				}
				atomic.AddInt64(&closedOK, 1)
			}(i)
		}
		ready.Wait()
		fmt.Printf("BARRIER all %d goroutines passed Create() stage; releasing writes\n", *count)
		close(release)
		wg.Wait()
		fmt.Printf("RACE count=%d created_ok=%d create_denied=%d closed_ok=%d\n",
			*count, createdOK, createDenied, closedOK)

	case "kill":
		// Write partial bytes then abruptly drop the TCP connection (no clean close).
		nc, cli, sf, err := dialRaw()
		if err != nil {
			fmt.Printf("KILL connect ERROR %v\n", err)
			return
		}
		f, err := sf.Create(*remote)
		if err != nil {
			fmt.Printf("KILL create ERROR %v\n", err)
			nc.Close()
			return
		}
		nw, werr := f.Write(payload(*size))
		fmt.Printf("KILL wrote=%d writeErr=%v; dropping TCP now (no SFTP close)\n", nw, werr)
		time.Sleep(300 * time.Millisecond) // let the server process the write packet
		nc.Close()                         // abrupt drop -> server sees EOF mid-transfer
		_ = cli
		fmt.Printf("KILL done remote=%s partial=%d\n", *remote, *size)

	case "hold":
		// Open `count` connections `stagger` ms apart; hold each `hold` seconds.
		var accepted, refused int64
		var wg sync.WaitGroup
		wg.Add(*count)
		for i := 0; i < *count; i++ {
			go func(idx int) {
				defer wg.Done()
				nc, cli, sf, err := dialRaw()
				if err != nil {
					atomic.AddInt64(&refused, 1)
					fmt.Printf("s%02d REFUSED %v\n", idx, err)
					return
				}
				atomic.AddInt64(&accepted, 1)
				fmt.Printf("s%02d ACCEPTED\n", idx)
				time.Sleep(time.Duration(*hold) * time.Second)
				sf.Close()
				cli.Close()
				nc.Close()
			}(i)
			if *stagger > 0 {
				time.Sleep(time.Duration(*stagger) * time.Millisecond)
			}
		}
		wg.Wait()
		fmt.Printf("HOLD count=%d accepted=%d refused=%d\n", *count, accepted, refused)

	case "idlehold":
		// Open a transfer, write partial bytes, then hold the connection open and
		// IDLE (no further writes, no close) so the server-side idle checker fires.
		nc, cli, sf, err := dialRaw()
		if err != nil {
			fmt.Printf("IDLEHOLD connect ERROR %v\n", err)
			return
		}
		f, err := sf.Create(*remote)
		if err != nil {
			fmt.Printf("IDLEHOLD create ERROR %v\n", err)
			nc.Close()
			return
		}
		nw, werr := f.Write(payload(*size))
		fmt.Printf("IDLEHOLD wrote=%d writeErr=%v; holding idle %ds\n", nw, werr, *idle)
		time.Sleep(time.Duration(*idle) * time.Second)
		f.Close()
		sf.Close()
		cli.Close()
		nc.Close()
		fmt.Printf("IDLEHOLD done remote=%s\n", *remote)
	}
}

func splitCSV(s string) []string {
	var out []string
	cur := ""
	for _, r := range s {
		if r == ',' {
			if cur != "" {
				out = append(out, cur)
			}
			cur = ""
		} else {
			cur += string(r)
		}
	}
	if cur != "" {
		out = append(out, cur)
	}
	return out
}
```

## 2. The mechanism (read from source, with verified `file:line`) — O6 coordination and the TOCTOU crux

This section states the code path as read from the source at HEAD `44634210`; every line number was re-verified against the checkout. The **behavioral consequences** are then demonstrated at runtime in §3, and each cross-reference notes where. Where a behavior is asserted from reading alone and was *not* exercised, it is marked **`[inferred]`**.

### 2.1 Shared registries and their guard (`sftpd/sftpd.go`)

A single package-level lock guards the in-memory registries:

- `var mutex sync.RWMutex` — `sftpd/sftpd.go:L56`; `var openConnections map[string]Connection` — `L57`; `var activeTransfers []*Transfer` — `L58`.
- Upload-mode constants `uploadModeStandard=0 / uploadModeAtomic=1 / uploadModeAtomicWithResume=2` — `sftpd/sftpd.go:L50-L52`; `isAtomicUploadEnabled()` returns `uploadMode==uploadModeAtomic || uploadMode==uploadModeAtomicWithResume` — `L414-L415`.
- The idle checker's ticker is created with a **hard-coded 5-minute period** in `init()`: `idleConnectionTicker = time.NewTicker(5 * time.Minute)` — `sftpd/sftpd.go:L132`. The configurable `idle_timeout` sets only the *threshold* (`startIdleTimer()` → `idleTimeout`), not the check cadence. Consequence observed in §3.5.
- `getActiveSessions(username)` counts `openConnections` for the user under `mutex.RLock()` — `sftpd/sftpd.go:L200`.

### 2.3 Quota limit check at file-open (`sftpd/handler.go`)

`hasSpace(checkFiles bool)` — `sftpd/handler.go:L515` — reads **committed** used-quota and denies on a `>=` threshold:

### 2.4 Completion-time quota update and the atomic rename/delete decision (`sftpd/transfer.go`)

`Transfer.Close()` — `sftpd/transfer.go:L121` — makes the atomic decision and performs the **positive completion-time quota update** for an upload (i.e. the increment that credits newly written bytes):

- atomic branch guard `transferType==transferUpload && file != nil && file.Name() != path` — `L134`;
- **success or resume**: `if t.transferError == nil || uploadMode == uploadModeAtomicWithResume` → `os.Rename(temp, target)` — `L136`, logged `atomic upload completed, rename: … error: <nil>` — `L137`;
- **errored, non-resume**: `os.Remove(temp)` — `L140`, logged `atomic upload completed with error: … delete temporary file: …` — `L141-L142`; on successful removal, `numFiles--` (`L144`) and `t.bytesReceived = 0` (`L145`);
- quota commit gate: `if transferType == transferUpload && (numFiles != 0 || bytesReceived > 0)` — `L166` → `dataprovider.UpdateUserQuota(...)` — `L167`.

Because this positive increment happens **only here at `Close()`**, and `hasSpace()` reads committed state at **open**, concurrent uploads that all open before any closes read the same stale value. `TransferError()` — `sftpd/transfer.go:L52` — records the first error and cancels the pipe (a dropped client surfaces as an `EOF` pipe error routed here). Consequences observed in §3.2/§3.4.

> **Lifecycle qualification (important, and the reason the above says “positive completion-time update”).** `Transfer.Close()` is the only quota mutation **for the new-file, positive-increment uploads exercised by this investigation** (baseline and burst create new files). It is **not** the only quota mutation across the *whole* upload lifecycle: for an **existing-file, non-resume overwrite**, `handleSFTPUploadToExistingFile()` issues a **pre-transfer decrement** `dataprovider.UpdateUserQuota(dataProvider, c.User, 0, -fileSize, false)` at `sftpd/handler.go:L486` (in the `else` branch, i.e. not an append/resume), *before* the transfer completes; the completion-time `Close()` update then re-adds the new size. Likewise a delete decrements at `handleSFTPRemove()` `dataprovider.UpdateUserQuota(dataProvider, c.User, -1, -size, false)` — `sftpd/handler.go:L405`. **`[inferred]`** — these existing-file/delete paths were **not** exercised here (the burst uploads only new files), so the overwrite pre-decrement is reported as an out-of-experiment lifecycle exception, not an observed value.

So `idle_timeout: 1` does **not** produce one-minute disconnects. The `m=+300s` cadence held on both independent starts (`m=+300.003914921` and `m=+300.004267446`) — stable. The distinguishing signal versus a client drop is the extra `close idle connection, idle time: …` line (`sftpd/sftpd.go:L348`).

### 3.7 Run-to-run distribution (magnitude/stability rule) — O1

Because the outcome is reported as run-to-run inconsistent, the **identical** contended burst was run repeatedly with the **canonical `max_sessions=3`** seed (not the §3.2 isolation control): `harness -mode burst -count 6 -size 700` from `0/0`, on the race build, **24 times** (two batches of 12 via `$WORK/dist_loop.sh`, which resets the DB and restarts the server each run). The number of sessions that win admission varies, and the final quota exactly tracks it.

```
$ "$WORK/dist_loop.sh"   # one line per run; excerpt

run  3: RACE count=6 created_ok=3 create_denied=0 closed_ok=3 | quota=3|2100 | data_race=0 | quota_exceed_logs=0
run  7: RACE count=6 created_ok=5 create_denied=0 closed_ok=5 | quota=5|3500 | data_race=0 | quota_exceed_logs=0
run  9: RACE count=6 created_ok=4 create_denied=0 closed_ok=4 | quota=4|2800 | data_race=0 | quota_exceed_logs=0
```

Aggregated admitted-count distribution over the 24 runs, and the resulting quota vs. the `3 / 3000` limit:

| admitted (= created_ok = closed_ok) | runs (of 24) | final quota | files vs 3 | size vs 3000 |
|---|---|---|---|---|
| 6 → `6 / 4200` | 14 | 6 files / 4200 B | over (2×) | over (1.4×) |
| 5 → `5 / 3500` | 3 | 5 files / 3500 B | over | over |
| 4 → `4 / 2800` | 2 | 4 files / 2800 B | over | under |
| 3 → `3 / 2100` | 5 | 3 files / 2100 B | at limit | under |

**Overshoot frequencies, stated explicitly (O1 direct answer):**

- **file quota over (`used_quota_files > 3`): 19 / 24 runs** (admitted 4, 5, or 6).
- **size quota over (`used_quota_size > 3000`): 17 / 24 runs** (admitted 5 or 6).
- **both limits over: 17 / 24 runs** (identical to the size-over set, because `size > 3000` requires ≥ 5 files, which is always also `files > 3`).
- **at least one limit over: 19 / 24 runs** (identical to the file-over set; the only file-over-but-size-under case is admitted = 4, i.e. 2 runs).
- The lone `admitted = 3` outcome (5 runs) hits the file limit **exactly** (`files = 3`, not over) and stays under on size (`2100`).

Invariants that held in **every** one of the 24 runs:

- `create_denied = 0` — the quota check **never** denied any transfer during the burst.
- `data_race = 0` — the `-race` build reported no data race in any run.
- `quota_exceed_logs = 0` during the burst — no enforcement fired for the racing transfers.
- `final quota == admitted × (1 file / 700 bytes)` **exactly** — accounting is **losslessly serialized**, no lost updates ever.

**Concrete cause of the inconsistency (not environmental).** Two compounding check-then-act races: the `max_sessions` TOCTOU (§2.2) decides how many of the six connections are admitted (variable 3–6), and every admitted upload then passes the quota TOCTOU (§2.3–§2.4) and commits, so the stored quota equals the admitted count × the per-file size. A representative partial run's full harness stdout:

```

g04 CONNECT-ERR ssh: handshake failed: ssh: unable to authenticate, attempted methods [password none], no supported methods remain
g05 CONNECT-ERR ssh: handshake failed: ssh: unable to authenticate, attempted methods [none password], no supported methods remain
g01 CONNECT-ERR ssh: handshake failed: ssh: unable to authenticate, attempted methods [none password], no supported methods remain
BARRIER all 6 goroutines passed Create() stage; releasing writes
RACE count=6 created_ok=3 create_denied=0 closed_ok=3
-> final quota (files|size): 3|2100
```
