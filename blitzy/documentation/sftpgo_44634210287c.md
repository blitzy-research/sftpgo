## 1. Direct answer

**The scanner's "OS command injection" finding is real but *conditional*, and the condition lives entirely in SFTPGo's runtime *configuration* — not in SFTPGo's own code.** SFTPGo never passes attacker-controlled data to a shell. Every one of its four command-execution sites uses Go's `os/exec` with an explicit argument vector (`exec.Command` / `exec.CommandContext`), which — per the official Go documentation — *"intentionally does not invoke the system shell"* ([pkg.go.dev/os/exec](https://pkg.go.dev/os/exec)). Consequently the classic `$(date +%s)` command-substitution payload is transmitted, stored, and forwarded as **literal bytes**; SFTPGo itself never expands it.

The scanner therefore flips between verdicts depending on how the operator configured the server:

- **"Not vulnerable"** — the default configuration (all action hooks empty) executes *nothing* (**observed:** condition C1). It stays "not vulnerable" even when a hook *is* configured, as long as that hook is a normal (non-shell) program: the payload arrives as a literal, unexpanded argument (**observed:** condition C2).
- **"Vulnerable"** — the operator configured an action hook that is itself a **shell wrapper** which re-evaluates the attacker-controlled filename (e.g. via `eval`/`sh -c`). Now *that shell* — not SFTPGo — expands `$(date +%s)`, and the attack fires (**observed:** condition C3, which created `/tmp/audit_1783999939.txt` and `/tmp/audit_1783999942.txt`, each containing `CONFIRMED`).

Both branches were reproduced with the **same unchanged malicious filename** `audit_$(date +%s).txt` uploaded over a real SFTP client, so the difference is attributable purely to configuration.

**Culprit component (named to `file:line`):** the file/SSH **action hook** in package `sftpd` — function `executeAction` → `executeNotificationCommand` in **`sftpd/sftpd.go`**, whose subprocess launch is `exec.CommandContext(ctx, actions.Command, operation, username, path, target, sshCmd)` at **`sftpd/sftpd.go:421`**, gated by the two guards at **`sftpd/sftpd.go:439`** and **`sftpd/sftpd.go:447`**. This is the site a scanner is most likely flagging, because the uploaded filename (attacker input) reaches its argv and its `SFTPGO_ACTION_PATH` environment variable. **However, line 421 is *not itself* an injection point** — it is a shell-free `execve`. The exploitable link is the *operator-supplied* `sftpd.actions.command` program when that program is a shell wrapper. Three sibling sites share the identical shell-free pattern and are analyzed in full: `sftpd/ssh_cmd.go:324` (SSH system commands), `dataprovider/dataprovider.go:742` (external auth), and `dataprovider/dataprovider.go:787` (user-management hook).

Everything below substantiates this answer with complete, reproducible runtime evidence.

## 4. The blocking mechanism, and CWE-78 vs CWE-88

**[OBSERVED + INFERRED]** Go's `os/exec` launches a child process via the POSIX `execve(2)` family with an explicit `argv` array; it does not interpose `/bin/sh -c`. The package documentation states this design intent directly — the package *"intentionally does not invoke the system shell and does not expand any glob patterns or handle other expansions, pipelines, or redirections typically done by shells"* ([go.dev/src/os/exec/exec.go](https://go.dev/src/os/exec/exec.go), lines 9-12). This is a **categorical property of the API**, not a sanitization routine that could be bypassed with clever encoding. `exec.CommandContext` is `exec.Command` plus a cancellation context ([go.dev/src/os/exec/exec.go](https://go.dev/src/os/exec/exec.go), `CommandContext`), so it inherits the same no-shell behavior.

Because of this:

- The bytes `$(date +%s)` inside the uploaded filename are delivered to the child as one literal `argv` element and as literal environment-variable content. Nothing in SFTPGo expands them. This is why C2 (a direct binary) created a file literally named `/tmp/audit_$(date +%s).txt` — the substitution was *never performed* (see §7, C2 hook record). **This is the exact blocker for the naive payload** (see §9).
- Expansion happens only if the *configured hook program is itself a shell* that re-parses the value — the C3 wrapper runs `eval "echo CONFIRMED > /tmp/$bn"`, and *that* shell performs the substitution.

**CWE mapping (narrowed):**

- **CWE-78 — *Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')*** ([MITRE CWE-78](https://cwe.mitre.org/data/definitions/78.html)). Classic `$(...)`, `;`, backtick, and pipe injection require a **shell interpreter** somewhere on the path. In SFTPGo, no such interpreter exists in-process; a CWE-78 condition materializes **only** when an operator supplies a shell-wrapper hook (C3). So the scanner's CWE-78 flag is accurate *about the deployed configuration*, and incorrect if attributed to SFTPGo's own code.
- **CWE-88 — *Improper Neutralization of Argument Delimiters in a Command ('Argument Injection')*** ([MITRE CWE-88](https://cwe.mitre.org/data/definitions/88.html)). Even with no shell, an attacker who controls `argv` elements can inject *options/flags* (e.g. a leading `-`/`--`) into a launched utility. The MITRE CWE-78 entry itself notes this overlap, describing an *"-exec"* switch as an argument-injection vector. This is the residual, distinct risk at **Site B** (SSH `rsync`/`git-*`), demonstrated in §7 (C5): the `$(date +%s)` name is *whitespace-tokenized* into separate `argv` items and passed to a really-executed `rsync`, but it is **not** command-substituted. SFTPGo mitigates the classic symlink argument-injection with `--safe-links`/`--munge-links` (README.md:159) and restricts the command *name* with a whitelist (`sftpd/ssh_cmd.go:51`).

### 6.1 `hook_direct.go` — a direct (non-shell) Site-A hook

Built with `GO111MODULE=off CGO_ENABLED=0 go build -o /tmp/audit/bin/hook_direct ./hook_direct.go` (exit 0; statically linked Go ELF). It uses only the Go standard library and never invokes a shell, so any `$(...)` in the payload cannot be expanded here; a failed evidence write calls `die()` and exits non-zero.

```go
// hook_direct.go — a DIRECT (non-shell) action-hook binary used to prove that
// SFTPGo hands the attacker-controlled filename to the hook as a LITERAL argv/env
// value (execve, no shell). It uses ONLY the Go standard library and never invokes
// a shell, so any $(...) in the payload cannot be expanded here.
//
// SFTPGo calls it as:  hook_direct <operation> <username> <path> <target> <sshCmd>
// with SFTPGO_ACTION_* environment variables also set.
//
// Robustness: every os.OpenFile / Write / Close error is checked and causes a
// non-zero exit, so a failed evidence write can never be mistaken for success.
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

// die prints an error to stderr and exits non-zero so the caller never mistakes
// a failed evidence write for a successful hook run.
func die(format string, a ...interface{}) {
	fmt.Fprintf(os.Stderr, "hook_direct FATAL: "+format+"\n", a...)
	os.Exit(1)
}

func main() {
	rec, err := os.OpenFile("/tmp/audit/evidence/hook_direct_record.txt",
		os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		die("cannot open record file: %v", err)
	}

	if _, err := fmt.Fprintf(rec, "=== hook_direct fired ===\n"); err != nil {
		die("record write failed: %v", err)
	}
	// effective identity of the spawned hook process (for the privilege finding)
	fmt.Fprintf(rec, "uid=%d euid=%d gid=%d egid=%d\n",
		os.Getuid(), os.Geteuid(), os.Getgid(), os.Getegid())
	fmt.Fprintf(rec, "argv (os.Args) = %#v\n", os.Args)
	actionPath := os.Getenv("SFTPGO_ACTION_PATH")
	fmt.Fprintf(rec, "SFTPGO_ACTION_PATH = %q\n", actionPath)

	// Create /tmp/<basename(SFTPGO_ACTION_PATH)> via Go os.Create — a LITERAL
	// filename. No shell, no expansion: filepath.Base keeps the bytes verbatim.
	target := "/tmp/" + filepath.Base(actionPath)
	fmt.Fprintf(rec, "creating (Go os.Create, NO shell) target = %q\n", target)
	f, err := os.Create(target)
	if err != nil {
		fmt.Fprintf(rec, "os.Create error: %v\n", err)
		rec.Close()
		die("os.Create(%q) failed: %v", target, err)
	}
	if _, err := f.WriteString("CONFIRMED\n"); err != nil {
		f.Close()
		rec.Close()
		die("write to %q failed: %v", target, err)
	}
	if err := f.Close(); err != nil {
		rec.Close()
		die("close of %q failed: %v", target, err)
	}
	fmt.Fprintf(rec, "wrote CONFIRMED to %q\n", target)
	if err := rec.Close(); err != nil {
		die("close of record file failed: %v", err)
	}
}
```

### 6.2 `hook_shell.sh` — a shell-wrapper Site-A hook (the operator misconfiguration)

This models the *only* configuration under which the naive payload fires. It is guarded so it evaluates **only** the exact known audit payload — a stray client cannot run arbitrary commands through it — and the `eval` result is checked so a failed write exits non-zero.

```sh
#!/bin/sh
# hook_shell.sh — a SHELL-WRAPPER action hook representing an ADMIN MISCONFIGURATION.
# Unlike SFTPGo's own code (which uses execve with an argv array and no shell), this
# admin-supplied script re-forwards the attacker-controlled filename into a shell via
# `eval` — the classic command-injection pattern. THIS shell, not SFTPGo, evaluates
# any $(...) embedded in the filename.
#
# SAFETY GUARD (bounds blast radius for this audit): eval is executed ONLY when the
# uploaded basename is EXACTLY the known expected audit payload. Any other filename is
# refused with a non-zero exit, so a stray client cannot run arbitrary commands here.
set -u
rec=/tmp/audit/evidence/hook_shell_record.txt
mkdir -p "$(dirname "$rec")" || { echo "hook_shell FATAL: cannot create record dir" >&2; exit 2; }
bn=$(basename "$SFTPGO_ACTION_PATH")
echo "[hook_shell] fired: euid=$(id -u) argv3=$3 SFTPGO_ACTION_PATH=$SFTPGO_ACTION_PATH basename=$bn" >> "$rec"
# GUARD: compare against the single-quoted LITERAL expected payload (not expanded here).
if [ "$bn" = 'audit_$(date +%s).txt' ]; then
    # THE VULNERABILITY: eval re-parses the filename as shell source, so the embedded
    # $(date +%s) command substitution is executed by this shell.
    if eval "echo CONFIRMED > /tmp/$bn"; then
        echo "[hook_shell] GUARD matched expected payload -> eval executed" >> "$rec"
        exit 0
    else
        echo "[hook_shell] GUARD matched but eval FAILED" >> "$rec"
        exit 3
    fi
else
    echo "[hook_shell] GUARD refused unexpected basename: $bn -> NO eval" >> "$rec"
    exit 1
fi
```

### 6.6 `extauth_prog` — a Site-C external-auth program (env-only, canary-safe, three modes)

### 6.7 `recorder.go` — a Site-B system-command stand-in (`rsync` / `git-upload-pack`)

The canonical Alpine image ships **neither** `rsync` **nor** `git-upload-pack` (§5.1), so this single static binary is installed on `PATH` under both names. ### 6.8 `sftp_harness` (`main.go`) — the real SFTP/SSH client

Module `auditharness` with its own `go.mod` copied from the SFTPGo manifest (same client-stack versions), built **offline** against the warmed module cache (`GOPROXY=off`, `CGO_ENABLED=0`), so the client stack is exactly the canonical `golang.org/x/crypto/ssh` + `github.com/pkg/sftp v1.11.0`; statically linked Go ELF. It performs **no** shell interpretation of the payload — the payload filename is passed as an exact Go string to the SFTP protocol, so any `$(...)` it contains is transmitted verbatim over the wire. A failed SSH exec (`session.Run` error) exits **non-zero**, and every mode validates its argument count **before** dialing.

```go
// main.go — throwaway SFTP/SSH client harness for the SFTPGo command-injection audit.
// It drives SFTPGo's REAL entry point over the canonical client stack:
//   golang.org/x/crypto/ssh  (SSH transport)  +  github.com/pkg/sftp (SFTP subsystem)
// It performs NO shell interpretation of the payload: the payload filename is passed
// as an exact Go string to the SFTP protocol, so any $(...) it contains is transmitted
// verbatim over the wire.
//
// Subcommands:
//   upload <remoteName>          create <remoteName> in the user's home and write 19 bytes
//   rename <srcName> <dstName>   create <srcName> then SFTP-rename it to <dstName>
//   download <remoteName>        open <remoteName> for reading (fires the download action)
//   pdownload <remoteName> <n>   PARTIAL read of n bytes then close early (SUPPRESSES the download action)
//   sshcmd <command...>          open an SSH "exec" session (NOT sftp) and run <command>
//   login                        attempt SSH auth only (used for the external-auth site)
//
// Credentials + host come from env: AUDIT_HOST, AUDIT_USER, AUDIT_PASS.
//
// Robustness (audit-integrity): a failed SSH exec (session.Run error) exits NON-ZERO, so
// a server-side command failure can never be recorded as a successful audit step. Every
// mode validates its argument count before dialing.
package main

import (
	"bytes"
	"fmt"
	"io"
	"os"
	"strings"
	"time"

	"github.com/pkg/sftp"
	"golang.org/x/crypto/ssh"
)

func dial() (*ssh.Client, error) {
	host := envOr("AUDIT_HOST", "127.0.0.1:2022")
	user := envOr("AUDIT_USER", "audituser")
	pass := os.Getenv("AUDIT_PASS")
	fmt.Printf(">> connecting to %s as %q over the real SSH transport (golang.org/x/crypto/ssh)\n", host, user)
	cfg := &ssh.ClientConfig{
		User:            user,
		Auth:            []ssh.AuthMethod{ssh.Password(pass)},
		HostKeyCallback: ssh.InsecureIgnoreHostKey(), // NON-CANONICAL host-key policy; acceptable for loopback test only
		Timeout:         10 * time.Second,
	}
	return ssh.Dial("tcp", host, cfg)
}

func envOr(k, d string) string {
	if v := os.Getenv(k); v != "" {
		return v
	}
	return d
}

func fail(msg string, err error) {
	fmt.Printf("!! ERROR: %s: %v\n", msg, err)
	fmt.Println("harness exit=1")
	os.Exit(1)
}

func usage(code int) {
	fmt.Println("usage: harness <upload|download|pdownload|rename|sshcmd|login> [args...]")
	os.Exit(code)
}

func main() {
	if len(os.Args) < 2 {
		usage(2)
	}
	mode := os.Args[1]

	// Validate argument counts BEFORE dialing so a usage error never partially runs.
	switch mode {
	case "upload", "download":
		if len(os.Args) < 3 {
			fmt.Printf("usage: harness %s <remoteName>\n", mode)
			os.Exit(2)
		}
	case "pdownload":
		if len(os.Args) < 4 {
			fmt.Println("usage: harness pdownload <remoteName> <nbytes>")
			os.Exit(2)
		}
	case "rename":
		if len(os.Args) < 4 {
			fmt.Println("usage: harness rename <srcName> <dstName>")
			os.Exit(2)
		}
	case "sshcmd":
		if len(os.Args) < 3 {
			fmt.Println("usage: harness sshcmd <command...>")
			os.Exit(2)
		}
	case "login":
		// no extra args
	default:
		fmt.Printf("unknown mode %q\n", mode)
		usage(2)
	}

	client, err := dial()
	if err != nil {
		// login mode treats an auth failure as an expected, reportable outcome
		if mode == "login" {
			fmt.Printf("!! auth/handshake result: %v\n", err)
			fmt.Println("harness exit=1")
			os.Exit(1)
		}
		fail("ssh.Dial failed", err)
	}
	defer client.Close()
	fmt.Println(">> SSH handshake + password auth SUCCEEDED")

	switch mode {
	case "login":
		fmt.Println(">> login-only mode: authenticated, no further action")
		fmt.Println("harness exit=0")

	case "upload":
		name := os.Args[2]
		sc, err := sftp.NewClient(client)
		if err != nil {
			fail("sftp.NewClient failed", err)
		}
		defer sc.Close()
		fmt.Println(">> SFTP subsystem opened (github.com/pkg/sftp)")
		fmt.Printf(">> payload filename (verbatim, len=%d) = %q\n", len(name), name)
		f, err := sc.Create(name)
		if err != nil {
			fail("sftp Create failed", err)
		}
		n, err := f.Write([]byte("audit-payload-20byt"))
		if err != nil {
			fail("sftp Write failed", err)
		}
		fmt.Printf(">> wrote %d bytes to the remote file\n", n)
		if err := f.Close(); err != nil {
			fail("sftp Close failed", err)
		}
		fmt.Println(">> f.Close() OK -> upload COMPLETED (fires the upload action)")
		listRoot(sc)
		fmt.Println("harness exit=0")

	case "download":
		name := os.Args[2]
		sc, err := sftp.NewClient(client)
		if err != nil {
			fail("sftp.NewClient failed", err)
		}
		defer sc.Close()
		fmt.Println(">> SFTP subsystem opened (github.com/pkg/sftp)")
		fmt.Printf(">> opening %q for read (fires the download action on close)\n", name)
		f, err := sc.Open(name)
		if err != nil {
			fail("sftp Open failed", err)
		}
		var buf bytes.Buffer
		nn, err := io.Copy(&buf, f)
		if err != nil {
			fail("sftp read failed", err)
		}
		if err := f.Close(); err != nil {
			fail("sftp Close failed", err)
		}
		fmt.Printf(">> read %d bytes then f.Close() OK -> download COMPLETED\n", nn)
		fmt.Println("harness exit=0")

	case "pdownload":
		name := os.Args[2]
		var nbytes int
		fmt.Sscanf(os.Args[3], "%d", &nbytes)
		sc, err := sftp.NewClient(client)
		if err != nil {
			fail("sftp.NewClient failed", err)
		}
		defer sc.Close()
		fmt.Println(">> SFTP subsystem opened (github.com/pkg/sftp)")
		fmt.Printf(">> PARTIAL read of %q: reading only %d byte(s) then closing early\n", name, nbytes)
		f, err := sc.Open(name)
		if err != nil {
			fail("sftp Open failed", err)
		}
		buf := make([]byte, nbytes)
		rn, rerr := io.ReadFull(f, buf)
		fmt.Printf(">> read %d byte(s) (err=%v); NOT reading the rest, closing now\n", rn, rerr)
		if err := f.Close(); err != nil {
			fmt.Printf(">> f.Close() returned: %v (server may report incomplete download)\n", err)
		}
		fmt.Println(">> partial download done -> SFTPGo should set transferError and SUPPRESS the download action")
		fmt.Println("harness exit=0")

	case "rename":
		src, dst := os.Args[2], os.Args[3]
		sc, err := sftp.NewClient(client)
		if err != nil {
			fail("sftp.NewClient failed", err)
		}
		defer sc.Close()
		fmt.Println(">> SFTP subsystem opened (github.com/pkg/sftp)")
		fmt.Printf(">> creating source %q then renaming to %q\n", src, dst)
		f, err := sc.Create(src)
		if err != nil {
			fail("sftp Create(src) failed", err)
		}
		if _, err := f.Write([]byte("audit-payload-20byt")); err != nil {
			fail("sftp Write(src) failed", err)
		}
		if err := f.Close(); err != nil {
			fail("sftp Close(src) failed", err)
		}
		fmt.Println(">> source created + closed (upload of source completes)")
		if err := sc.Rename(src, dst); err != nil {
			fail("sftp Rename failed", err)
		}
		fmt.Printf(">> Rename(%q -> %q) OK -> fires the rename action\n", src, dst)
		listRoot(sc)
		fmt.Println("harness exit=0")

	case "sshcmd":
		cmd := strings.Join(os.Args[2:], " ")
		sess, err := client.NewSession()
		if err != nil {
			fail("NewSession failed", err)
		}
		defer sess.Close()
		fmt.Println(">> opening SSH session (exec channel), NOT the SFTP subsystem")
		fmt.Printf(">> session.Run(%q) — drives sftpd/ssh_cmd.go processSSHCommand\n", cmd)
		var out bytes.Buffer
		sess.Stdout = &out
		sess.Stderr = &out
		runErr := sess.Run(cmd)
		fmt.Printf(">> combined output (%d bytes): %q\n", out.Len(), out.String())
		if runErr != nil {
			// A failed SSH command is a NON-ZERO harness result, so a server-side
			// rejection/failure is never mistaken for a successful audit step.
			fmt.Printf(">> session exited with ERROR: %v\n", runErr)
			fmt.Println("harness exit=1")
			os.Exit(1)
		}
		fmt.Println(">> session exited cleanly (no error)")
		fmt.Println("harness exit=0")
	}
}
```

### 6.9 `lib.sh` — server lifecycle & bounded polling

Sourced by each condition runner. It forces the log path absolute (so logs never land in the repo), binds loopback only, tracks the exact PID for a precise kill (never `pkill`/`killall`), **kills the exact PID it started if readiness times out or the process dies during startup** (never leaking a half-started server), and provides a **bounded** `poll_log` used to await the asynchronous hook goroutine (addresses the race for Site A's `go executeAction(...)`).

```sh
# lib.sh — server lifecycle + polling helpers for the SFTPGo command-injection audit.
# Sourced by each condition runner. All servers bind LOOPBACK ONLY and are tracked by
# exact PID so they can be killed precisely (never pkill/killall). The log file path is
# forced ABSOLUTE (SFTPGO_LOG_FILE_PATH) so it is always written under /tmp/audit/run
# regardless of the current working directory (never into the repo).
RUN=/tmp/audit/run
BIN=/tmp/sftpgo_bin
LOG="$RUN/sftpgo.log"
SRV=""

# start_server "<ENV assignments>"  -> starts server with fresh logs, waits for :2022 listener.
# On readiness FAILURE it kills the exact PID it started (never leaks a half-started server)
# and returns non-zero. The readiness probe matches ANY local_address ending in :07E6 in the
# LISTEN state (0A), so it works for both the loopback (0100007F) and wildcard (00000000) forms.
start_server() {
    local envassign="$1"
    rm -f "$LOG" "$RUN/console.log"
    # shellcheck disable=SC2086
    env SFTPGO_LOG_FILE_PATH="$LOG" $envassign nohup "$BIN" serve -c "$RUN" > "$RUN/console.log" 2>&1 &
    SRV=$!
    local i
    for i in $(seq 1 40); do
        if awk '$2 ~ /:07E6$/ && $4=="0A"{f=1} END{exit !f}' /proc/net/tcp 2>/dev/null; then
            sleep 0.3
            return 0
        fi
        # if the process died during startup, stop waiting
        kill -0 "$SRV" 2>/dev/null || { echo "!! server pid=$SRV exited during startup"; wait "$SRV" 2>/dev/null; SRV=""; return 1; }
        sleep 0.5
    done
    echo "!! server did not bind :2022 within timeout (pid=$SRV) -> killing it"
    kill "$SRV" 2>/dev/null
    for i in $(seq 1 20); do kill -0 "$SRV" 2>/dev/null || break; sleep 0.25; done
    kill -9 "$SRV" 2>/dev/null
    wait "$SRV" 2>/dev/null
    SRV=""
    return 1
}

# stop_server -> kills exactly the PID we started, verifies it is gone
stop_server() {
    [ -n "$SRV" ] || return 0
    kill "$SRV" 2>/dev/null
    local i
    for i in $(seq 1 20); do kill -0 "$SRV" 2>/dev/null || break; sleep 0.25; done
    if kill -0 "$SRV" 2>/dev/null; then echo "!! PID $SRV still alive"; else echo "server pid=$SRV stopped"; fi
    SRV=""
}

# poll_log <timeout_s> <pattern> -> waits up to <timeout_s> for <pattern> in the server log.
# returns 0 if it appears, 1 on timeout (bounds async goroutine completion).
poll_log() {
    local timeout="$1" pat="$2" i
    for i in $(seq 1 $((timeout*4))); do
        grep -q "$pat" "$LOG" 2>/dev/null && return 0
        sleep 0.25
    done
    return 1
}

show_listener() { awk 'NR==1 || ($2 ~ /:07E6$/ && $4=="0A")' /proc/net/tcp; }
show_artifacts() { ls -la /tmp/audit_*.txt 2>&1; }
```

```python
#!/usr/bin/env python3
# rest.py -- minimal REST client for the SFTPGo management API (127.0.0.1:8080).
# The Alpine image has no curl; this uses python3 urllib (always present) and prints
# the HTTP status code and the COMPLETE, unedited response body for every call,
# including 4xx/5xx (caught, never swallowed) -- needed for the API acceptance matrix.
import sys, json, urllib.request, urllib.error

BASE = "http://127.0.0.1:8080"

def call(method, path, body=None):
    url = BASE + path
    data = None
    headers = {}
    if body is not None:
        if isinstance(body, (dict, list)):
            data = json.dumps(body).encode()
        else:
            data = body.encode() if isinstance(body, str) else body
        headers["Content-Type"] = "application/json"
    req = urllib.request.Request(url, data=data, method=method, headers=headers)
    try:
        with urllib.request.urlopen(req, timeout=10) as r:
            code = r.getcode()
            payload = r.read().decode(errors="replace")
    except urllib.error.HTTPError as e:
        code = e.code
        payload = e.read().decode(errors="replace")
    except Exception as e:
        print("REQUEST_ERROR:", repr(e)); sys.exit(2)
    print("HTTP_STATUS:", code)
    print("RESPONSE_BODY:", payload)
    return code, payload

if __name__ == "__main__":
    # usage: rest.py <METHOD> <PATH> [body-json-string | @-  for stdin | @file]
    method, path = sys.argv[1], sys.argv[2]
    body = None
    if len(sys.argv) > 3:
        arg = sys.argv[3]
        if arg == "@-":
            body = sys.stdin.read()
        elif arg.startswith("@"):
            body = open(arg[1:]).read()
        else:
            body = arg
    call(method, path, body)
```

All observations flow through the **real** SFTP/SSH entry point (`golang.org/x/crypto/ssh` + `github.com/pkg/sftp`) or the **real** management REST API — never a mock, debug hook, or synthetic bypass. ## 8. The target artifact (the user's requested proof)

The user asked the attack to create `/tmp/audit_$(date +%s).txt` containing `CONFIRMED`. This was achieved at runtime in **condition C3** (Site A shell-wrapper hook), and reproduced independently at **Site D** (the shell-wrapper user-action hook, §7.8).

- **Exact payload string (unchanged across all conditions):** `audit_$(date +%s).txt` (21 bytes)
- **Exact resolved filenames created at Site A (C3), with timestamps — two full trials plus one fresh cohesive end-to-end trial (§7.4):**
  - `/tmp/audit_1783999939.txt` — created `2026-07-14T03:32:19` (trial 1); epoch `1783999939` decodes to that same second
  - `/tmp/audit_1783999942.txt` — created `2026-07-14T03:32:22` (trial 2)
  - `/tmp/audit_1783999944.txt` — created `2026-07-14T03:32:24` (fresh cohesive trial; its `cat` output `CONFIRMED` is shown at the end of the §7.4 block)
  - **Content of each:** `CONFIRMED` — **10 bytes** (the hook uses `echo`, which appends a trailing newline)
- **Independent reproduction at Site D (shell-wrapper user-action hook, §7.8):**
  - `/tmp/audit_1784000782.txt` — created `2026-07-14T03:46:22`; **Content:** `CONFIRMED` — **9 bytes** (this hook uses `printf` with no trailing newline)
- **Diagnostic oracle (per AAP §0.5.3).** The resolved names above carry a *decimal epoch* (`1783999944`), proving a shell executed `$(date +%s)`. Contrast C2/D-direct, where the artifact is literally named `audit_$(date +%s).txt` with the `$(...)` **unexpanded** — proving no shell was involved. The literal-vs-expanded filename is itself the signal that distinguishes the two branches.
- **Distribution across the run-to-run reproduction:** with a shell-wrapper hook configured, **every** trial fired and produced a fresh epoch-named file (the epoch advances per second, which is why the filenames differ). With the default (C1) or direct-binary (C2/D-direct) configurations, **every** trial produced **no** such file. The behavior is therefore deterministic *per configuration*; the scanner's "sometimes vulnerable / sometimes not" is a **cross-configuration** artifact, not in-configuration flakiness.

## 9. Where the attack does NOT fire — the exact blocker

In C1/C1b/C1c/C1d (no eligible hook) nothing runs, so there is nothing to block at the exec layer — the guards at `sftpd/sftpd.go:439`/`:447` short-circuit first.

In **C2/C2-rename** (a hook *does* run) and in **C4/C5/C6**, the naive `$(date +%s)` payload is **blocked from expanding** by one concrete mechanism:

> SFTPGo launches every subprocess with Go's `os/exec` (`exec.Command`/`exec.CommandContext`), which performs an `execve` with an explicit `argv` array and **does not invoke `/bin/sh -c`**. The bytes `$(date +%s)` are therefore delivered to the child as literal `argv` bytes and/or as literal environment content, and no component in SFTPGo's process re-parses them as shell source. The exact argv *shape* differs per site: Sites A and D deliver the payload as a **single** literal `argv` element (the filename/username is one field), whereas Site B **splits it on whitespace** via `strings.Split(command," ")` (`sftpd/ssh_cmd.go:423-424`), so it arrives as **two** literal tokens (`audit_$(date` and `.../+%s).txt`) — observed in §7.7. In no case is the `$(...)` executed.

The **observed proof** is the C2 hook record in §7.2: the file SFTPGo's hook created is literally named `/tmp/audit_$(date +%s).txt` — the substitution was never performed. The corollary is the C3 result: expansion appears **only** once an operator inserts a shell (`eval`) into the hook program. So the blocker for the "vulnerable" verdict is the absence of a shell in SFTPGo's code path; the enabler is an operator-supplied shell wrapper.

For Site B specifically, the additional blocker against introducing a *new* command is the command-name whitelist (`sftpd/ssh_cmd.go:51`, observed in §7.7 B1), and the mitigation against symlink argument-injection is `--safe-links` / `--munge-links` (both branches observed in §7.7 B3 and the C5b block).

## 10. Effective privilege of a fired hook (platform-scoped)

**[OBSERVED at runtime, Unix — Sites A, C, D run as the server owner]** The server process runs as root in this container (`/proc/<pid>/status` → `Uid: 0 0 0 0`, §5.7). Every hook that fired at Site A, C, or D recorded `uid=0 euid=0 gid=0 egid=0` (the C2/C3 Site-A hook records in §7.2/§7.4, the C4 Site-C external-auth record in §7.6, and the C6 Site-D hook record in §7.8) — i.e. those hooks ran as the SFTPGo process owner (root here), **not** dropped to the mapped user. That matches the source: Sites A, C, and D call `exec.Command`/`CommandContext` **without** `wrapCmd`, so no credential drop is applied.

**[OBSERVED at runtime, Unix — Site B drops to the mapped user]** Only **Site B** applies a privilege drop, and it was confirmed **at runtime**, not merely read from source: the instrumented `recorder` standing in for `rsync`/`git-upload-pack` printed its own effective identity as `runtime identity: uid=1000 euid=1000 gid=1000 egid=1000` (§7.7, conditions B3/B4 and the `--munge-links` block) — exactly the `uid`/`gid` `1000`/`1000` of the mapped SFTP user, proving the child was launched with dropped credentials. The drop is applied at `sftpd/ssh_cmd.go:327` via `wrapCmd` (`sftpd/cmd_unix.go`), which sets `SysProcAttr.Credential{Uid,Gid}` when `uid>0 || gid>0`:

```
# sftpd/cmd_unix.go
func wrapCmd(cmd *exec.Cmd, uid, gid int) *exec.Cmd {
	if uid > 0 || gid > 0 {
		cmd.SysProcAttr = &syscall.SysProcAttr{}
		cmd.SysProcAttr.Credential = &syscall.Credential{Uid: uint32(uid), Gid: uint32(gid)}
	}
	return cmd
}
```

**[INFERRED, Windows]** On Windows the build uses `sftpd/cmd_windows.go`, where `wrapCmd` is a no-op (`return cmd`). This is read from source; it was **not** observed at runtime (the audit ran on Linux only). The practical implication (inferred): on Unix, a misconfigured shell-wrapper hook at Site B would run with the mapped user's reduced privileges, whereas Sites A/C/D hooks run with the server's privileges; on Windows no drop occurs for any site.

### 12.1 Adjacent security observations (INFORMATIONAL — remediation out of scope)

Two pre-existing security postures were observed during the audit. They are **outside** the command-injection question and their remediation is explicitly out of scope for this read-only investigation (AAP §0.3.2 — "remediation … is explicitly out of scope; the task is to explain and demonstrate, not to fix"). They are recorded here honestly rather than fixed:

- **[OBSERVED] External-auth failure logs the full environment, including the cleartext password.** On a non-zero external-auth exit, `doExternalAuth` wraps `cmd.Env` into the returned error via `%+v` (`dataprovider/dataprovider.go:748-749`), and that error is logged at WARN/DEBUG. Because credentials are passed to the hook as `SFTPGO_AUTHD_PASSWORD` (env, not argv), the cleartext password appears verbatim in the log line — reproduced at runtime in §7.6 with the fabricated probe secret `ProbeSecret_LEAKME_x7y9`. This is a log-hygiene weakness in this `0.9.5-dev` baseline; it is noted, not remediated.
- **[OBSERVED] The REST management API is unauthenticated on the loopback interface in this baseline.** Every provisioning call in §5.6/§5.8 (`POST/GET/PUT/DELETE /api/v1/user`) succeeded with **no** credentials or CSRF token against `127.0.0.1:8080`. This is the historical management-API posture of the `0.9.5-dev` tree (later SFTPGo releases add authentication); it is called out here for completeness and, per the scope above, is not changed.
