# SFTPGo Security-Model Investigation — SSH Commands, SCP Parsing, Permissions & Path Containment

**Target under investigation:** SFTPGo `0.9.5-dev` — module `github.com/drakkan/sftpgo` (`go.mod`), Go directive `go 1.13`.
**Source branch the deliverable is named after:** `sftpgo_44634210287c` (hence this file is `blitzy/documentation/sftpgo_44634210287c.md`).

This document answers six security-model questions about how SFTPGo behaves when external file-synchronization utilities and SSH commands are invoked. It is **evidence-driven**: every behavioral claim is backed by output captured from *actually running* the built binary and driving it through a **real client** (system `ssh`/`scp`/`sftp`/`rsync`, or crafted SCP protocol bytes over an SSH `exec` channel). The methodology was **run first, write second** — the code was built, launched in its default (canonical) configuration, exercised through its genuine client-facing entry points, and only then documented.

Statements that could only be derived by *reading* the code (never observed at runtime) are explicitly labeled **`(inferred)`**. Everything else is anchored both to a `file:line` code reference **and** to captured runtime output (the exact command, its complete unedited output, and its exit status).

> **Scope note (read-only).** No SFTPGo source, test, or configuration file was modified. The only artifact added to the repository is this single Markdown document (and its parent directory `blitzy/documentation/`). All transient artifacts used to capture evidence — the built binary, a temporary SQLite database, generated host keys, test-user home directories, and throwaway scripts — were created **outside** the repository tree (under `/tmp`) and deleted before completion. The closing "Cleanup & verification" section pastes the final `git status --porcelain` as proof.

### Evidence conventions

- **Every claim** is backed by the *exact* command actually executed (the `$` line), its **complete, unedited** client stdout/stderr, and its explicit `[exit status: N]`.
- **Server-log excerpts** show the lines the server emitted *for that command* (login, `ssh`/`sftpd` dispatch, transfer notifications, warnings, connection add/remove). The only lines omitted are the harness's benign TCP **readiness-probe** noise (`failed to accept an incoming connection: EOF` / `no_auth_tryed`) produced by a port check unrelated to the command; nothing from the command's own handling is elided. The `connection_id` in each excerpt ties the log lines to that one invocation.
- The seed file `/tmp/sftpgo_run/testuser/probe.txt` contains exactly `hello world\n` (12 bytes) throughout, so its hashes are fixed: MD5 `6f5902ac237024bdd0c176cb93063dc4`, SHA1 `22596363b3de40b06f981fb85d82312e8c0ed511`, SHA256 `a948904f2f0f479b8f8197694b30184b0d2ed1c1cd2a1ec0fb85d299a192a447`.

Consequently `connection_id`s and log timestamps differ from one section to the next; each individual block is internally consistent (its command, output, and log share one connection), and the exact configuration in force is stated at the start of each block. Two sections (Q1d and Q3c) were re-executed in a later dedicated run to capture complete runtime evidence for every named item (all three unsupported names including `sftpgo-remove`) and the non-local backend gate; those two sections therefore also carry a freshly-generated throwaway-key fingerprint and later timestamps, but are each fully self-consistent internally. ## Q1 — Enabling / disabling external utilities (the SSH-command allowlist)

### Direct finding

SFTPGo governs external utilities and SSH commands through a **fixed allowlist of supported names** plus a **configurable enabled subset**. Concretely:

- The complete set of names SFTPGo will *ever* accept is hard-coded as `supportedSSHCommands` = `{scp, md5sum, sha1sum, sha256sum, sha384sum, sha512sum, cd, pwd, git-receive-pack, git-upload-pack, git-upload-archive, rsync}`. Anything outside this set can never be enabled.
- The subset active by default is `defaultSSHCommands` = `{md5sum, sha1sum, cd, pwd}`.
- **`scp` is *not* enabled by default**; it is gated by a *separate* boolean `enable_scp` (default `false`).
- **`rsync` is *not* enabled by default**; it must be added to `enabled_ssh_commands`.
- Observed at runtime: with defaults, both `scp` (legacy protocol) and `rsync` are **refused**; after enabling them, they are **accepted**; an unsupported name placed in `enabled_ssh_commands` is **silently dropped at startup with a warning**; and the wildcard `"*"` expands to the **entire supported set**.
- **`sftpgo-copy` / `sftpgo-remove` do NOT exist in this revision.** They are built-in SSH commands in later SFTPGo 2.x releases, but here they are neither in `supportedSSHCommands` nor recognized anywhere — a name like `sftpgo-copy` is treated exactly like any other unsupported string (dropped at startup, refused at runtime). This is demonstrated in Q1d below.

### Code anchors

- Name lists — `sftpd/sftpd.go:L66-70`:
  - `supportedSSHCommands` (L66-67), `defaultSSHCommands` (L68), `sshHashCommands` (L69), `systemCommands` (L70).
  - Accessors `GetDefaultSSHCommands` (`sftpd/sftpd.go:L136`), `GetSupportedSSHCommands` (`sftpd/sftpd.go:L143`).
- Defaults — `config/config.go`: `BindPort:2022` (L46), `IsSCPEnabled:false` (L58), `EnabledSSHCommands: sftpd.GetDefaultSSHCommands()` (L63), `Driver:"sqlite"` (L66), `Name:"sftpgo.db"` (L67). - Startup normalization — `sftpd/server.go` `checkSSHCommands` (L396-414): `"*"` → `GetSupportedSSHCommands()` and early-return (L397-399); if `IsSCPEnabled` then `"scp"` is prepended (L402-404); any entry not in `supportedSSHCommands` is dropped with a log `unsupported ssh command: %#v ignored` (L406-411, warning emitted at L409-410).

```go
// sftpd/server.go:L396-414
func (c *Configuration) checkSSHCommands() {
    if utils.IsStringInSlice("*", c.EnabledSSHCommands) {
        c.EnabledSSHCommands = GetSupportedSSHCommands()
        return
    }
    sshCommands := []string{}
    if c.IsSCPEnabled {
        sshCommands = append(sshCommands, "scp")
    }
    for _, command := range c.EnabledSSHCommands {
        if utils.IsStringInSlice(command, supportedSSHCommands) {
            sshCommands = append(sshCommands, command)
        } else {
            logger.Warn(logSender, "", "unsupported ssh command: %#v ignored", command)
            logger.WarnToConsole("unsupported ssh command: %#v ignored", command)
        }
    }
    c.EnabledSSHCommands = sshCommands
}
```

## Q2 — The client / server control boundary

### Direct finding

**The client fully controls the raw command *string*; the server alone decides whether to honor it.** A client can send *any* string in an SSH `exec` request — `whoami`, `ls -la /etc`, `rsync ...`, anything. SFTPGo unmarshals that string, tokenizes it, logs it verbatim (proving it arrived), and then applies the allowlist gate. Only names present in the enabled set are dispatched; everything else is refused with `ssh command not enabled/supported: %#v` and the channel reply is `false`. So the boundary is: **client = arbitrary command text in; server = allowlist decision + dispatch.**

### Causal explanation

The `md5sum` string produced `new ssh command: "md5sum" ... error: <nil>` and **no** rejection line, so it passed the `utils.IsStringInSlice(name, enabledSSHCommands)` gate (`sftpd/ssh_cmd.go:L51`) and was dispatched, returning the hash and exit 0. `whoami`, `ls`, and `rsync` each produced a `new ssh command` line (the server received exactly what the client typed) **followed by** `ssh command not enabled/supported`, so `processSSHCommand` returned `false`, and `server.go`'s `req.Reply(false, nil)` (`sftpd/server.go:L329`) is what the client surfaces as `exec request failed on channel 0` / exit 255. Note `ls -la /etc` was tokenized to name=`ls`, args=`[-la /etc]` — the naive space split (see Q4) — and rejected on the **name** `ls`. This is the precise client/server boundary: the client dictates the string; the server's allowlist dictates the outcome.

## Q3 — Filtering / validation rules

### Direct finding

Acceptance and validation of SSH commands is layered:

1. **Allowlist membership** decides acceptance, computed by one primitive: `utils.IsStringInSlice` (a linear equality scan). The *same* primitive is used at startup normalization, at the runtime gate, and for command routing.
2. **Command routing** in `handle` classifies an accepted command into one of four handlers: hash commands, system commands, `cd` (no-op, exit 0), or `pwd` (writes a hard-coded `"/"`).
3. **A local-filesystem capability gate** restricts *hash* and *system* commands to the local (OS) backend; on a non-local backend they return `errUnsupportedConfig` ("command unsupported for this configuration").
4. **rsync-specific argument injection**: the destination argument is resolved to an absolute path and substituted, and a symlink-safety flag is injected — `--safe-links` if the user has `create_symlinks`, otherwise `--munge-links`.
5. Spawned system commands run under the user's mapped uid/gid via `wrapCmd`.

### Code anchors

- Allowlist primitive — `utils/utils.go:L20-27` `IsStringInSlice`.
- Router — `sftpd/ssh_cmd.go:L83-103` `handle`: hash → `handleHashCommands` (L87-88); system → `getSystemCommand`+`executeSystemCommand` (L89-94); `cd` → `sendExitStatus(nil)` (L95-96); `pwd` → `channel.Write([]byte("/\n"))` + exit (L97-100).
- Local-fs gate — `handleHashCommands` (`sftpd/ssh_cmd.go:L106-108`) and `executeSystemCommand` (`sftpd/ssh_cmd.go:L152-153`) both `return c.sendErrorResponse(errUnsupportedConfig)` when `!vfs.IsLocalOsFs(c.connection.fs)`. `IsLocalOsFs` = `fs.Name() == osFsName` (`vfs/vfs.go:L67-69`).
- System-command permission set — `executeSystemCommand` (`sftpd/ssh_cmd.go:L158-160`): `HasPerms([download, upload, create_dirs, list, overwrite, delete, rename], getDestPath())`.
- rsync injection — `getSystemCommand` (`sftpd/ssh_cmd.go:L306-322`): `HasPerm(PermCreateSymlinks, ...)` → prepend `--safe-links` if absent (L313-316); else prepend `--munge-links` if absent (L317-320); DEBUG log `new system command %#v, with args: %v path: %v` (L323); `exec.Command` (L324) → `wrapCmd(cmd, uid, gid)` (L325-327).
- uid/gid credential — `sftpd/cmd_unix.go:L10-15` `wrapCmd`: sets `SysProcAttr.Credential = &syscall.Credential{Uid, Gid}` only `if uid > 0 || gid > 0`.
- Error variables — `sftpd/ssh_cmd.go`: `errQuotaExceeded` ("denying write due to space limit", L29), `errPermissionDenied` ("Permission denied. You don't have the permissions to execute this command", L30), `errUnsupportedConfig` ("command unsupported for this configuration", L31).

### Q3c — Local-filesystem gate

On the default **local** backend (`osfs`), hash commands run normally (this is the acceptance path shown throughout — e.g. `md5sum` in Q2 and `sha256sum` in Q1e both returned correct digests, exit 0). The complementary rejection — a *non-local* backend returning `errUnsupportedConfig` — is **observed at runtime** (below). Both touch points apply the identical guard `!vfs.IsLocalOsFs(c.connection.fs)`: `handleHashCommands` (`sftpd/ssh_cmd.go:L106-108`) and `executeSystemCommand` (`sftpd/ssh_cmd.go:L152-153`), each returning `errUnsupportedConfig` = `"command unsupported for this configuration"` (`sftpd/ssh_cmd.go:L31`).

```go
// sftpd/ssh_cmd.go:L105-108 (hash gate); executeSystemCommand L151-153 applies the identical guard
func (c *sshCommand) handleHashCommands() error {
    if !vfs.IsLocalOsFs(c.connection.fs) {
        return c.sendErrorResponse(errUnsupportedConfig)
    }
```

This gate is reachable **offline** because it depends only on the connected user's *provider type*, not on any live object-storage connectivity: a user with `filesystem.provider:1` resolves to `vfs.NewS3Fs` (`dataprovider/user.go:L113`), whose AWS session is created lazily (`session.NewSession` performs no network I/O at construction), and `S3Fs.Name()` returns `"S3Fs bucket: …"` so `vfs.IsLocalOsFs` (`vfs/vfs.go:L67`) is false. ## Q4 — Delimiter / boundary assumptions under unusual input

### Direct finding

Two parsers carry baked-in delimiter assumptions, and both break in predictable ways on unusual input:

1. **SSH command tokenizer** (`parseCommandPayload`) splits the command string on a **single space** with **no quoting/escaping awareness**. A double space yields an empty token; multi-word commands are split into name + remaining tokens.
2. **SCP upload-header parser** (`parseUploadMessage`) assumes each `C`/`D` header is exactly **three space-separated parts** (`<mode> <size> <name>`). Consequences observed at runtime:
   - a filename **containing a space** produces **more than three** parts → `Error splitting upload message`;
   - a header **not starting with `C` or `D`** → `unknown or invalid upload message`;
   - an **empty name** → `error getting name from upload message, cannot be empty`;
   - a **non-numeric size** → `Error getting size: strconv.ParseInt: ... invalid syntax`.
   In **every** malformed case, **no file is created** (before/after home listing identical).
3. SCP protocol messages are **newline-terminated and read one byte at a time** (`readProtocolMessage`).

### Code anchors

- Tokenizer — `sftpd/ssh_cmd.go:L423-429` `parseCommandPayload`: `parts := strings.Split(command, " ")`; `if len(parts) < 2 { return parts[0], []string{}, nil }`; else `return parts[0], parts[1:], nil`.
- Byte-by-byte newline reader — `sftpd/scp.go:L542-564` `readProtocolMessage`: `buf := make([]byte, 1)`; loop reads 1 byte; `if n == 1 && readed[0] == newLine[0] { break }`.
- Header parser — `sftpd/scp.go:L631-664` `parseUploadMessage`:
  - not `C`/`D` → `unknown or invalid upload message: %v args: %v user: %v` (L635-636);
  - `parts := strings.Split(command, " ")` (L642), `if len(parts) == 3` (L643);
  - `strconv.ParseInt` failure → `Error getting size: %v` (L646-647);
  - `name = parts[2]`; empty → `error getting name from upload message, cannot be empty` (L650-652);
  - otherwise (≠3 parts) → `Error splitting upload message: %v` (L657-658).

```go
// sftpd/scp.go:L631-664 (parseUploadMessage — exactly-three-parts assumption)
func (c *scpCommand) parseUploadMessage(command string) (int64, string, error) {
    var size int64
    var name string
    var err error
    if !strings.HasPrefix(command, "C") && !strings.HasPrefix(command, "D") {
        err = fmt.Errorf("unknown or invalid upload message: %v args: %v user: %v",
            command, c.args, c.connection.User.Username)
        c.connection.Log(logger.LevelWarn, logSenderSCP, "error: %v", err)
        c.sendErrorMessage(err.Error())
        return size, name, err
    }
    parts := strings.Split(command, " ")
    if len(parts) == 3 {
        size, err = strconv.ParseInt(parts[1], 10, 64)
        if err != nil {
            c.connection.Log(logger.LevelWarn, logSenderSCP, "error getting size from upload message: %v", err)
            c.sendErrorMessage(fmt.Sprintf("Error getting size: %v", err))
            return size, name, err
        }
        name = parts[2]
        if len(name) == 0 {
            err = fmt.Errorf("error getting name from upload message, cannot be empty")
            c.connection.Log(logger.LevelWarn, logSenderSCP, "error: %v", err)
            c.sendErrorMessage(err.Error())
            return size, name, err
        }
    } else {
        err = fmt.Errorf("Error splitting upload message: %v", command)
        c.connection.Log(logger.LevelWarn, logSenderSCP, "error: %v", err)
        c.sendErrorMessage(err.Error())
        return size, name, err
    }
    return size, name, err
}
```

## Q5 — Where permission checks sit in the chain (resolve-then-authorize)

### Direct finding

**Path resolution/normalization runs *before* the authorization check.** In the SCP upload path, `ResolvePath` is called first; only afterward is `HasPerm` consulted — `PermUpload` on the parent directory for a *new* file, or `PermOverwrite` on the target for an *existing* file. The permission model itself is a **per-directory, deepest-match** lookup: `GetPermissionsForPath` returns the permissions of the **most specific** configured directory that is a prefix of the target, so a permission granted at `/` can be **overridden** (narrowed) at a subdirectory. This ordering matters: a path that resolves successfully can still be denied, and the denial is decided by the *deepest* matching directory's permission set — not by the root grant.

### Code anchors

- SCP upload — `sftpd/scp.go:L226-285` `handleUpload`:
  - `p, err := c.connection.fs.ResolvePath(uploadFilePath)` **first** (L231); on error → `error uploading file` + return (L232-235).
  - `stat, statErr := c.connection.fs.Stat(p)` (L241).
  - new file (does not exist): `if !c.connection.User.HasPerm(dataprovider.PermUpload, path.Dir(uploadFilePath))` → `Permission denied`, log `cannot upload file: %#v, permission denied` (L242-248).

```go
func (u *User) GetPermissionsForPath(p string) []string {
    permissions := []string{}
    if perms, ok := u.Permissions["/"]; ok {
        // if only root permissions are defined returns them unconditionally
        if len(u.Permissions) == 1 {
            return perms
        }
        permissions = perms  // fallback
    }
    // ... builds dirsForPath in reverse (deepest first) ...
    for _, val := range dirsForPath {
        if perms, ok := u.Permissions[val]; ok {
            permissions = perms
            break   // first (deepest) match wins
        }
    }
    return permissions
}
```

## Q6 — Protections against filesystem tricks (path traversal / containment)

### Direct finding

SFTPGo's local-backend protection is `OsFs.ResolvePath`, which **joins the request onto the user's root, `filepath.Clean`s it, evaluates symlinks, and then confirms containment** via `isSubDir`. A separate, complementary guard — `OsFs.GetRelativePath` (`vfs/osfs.go:L183-192`) — protects the home root itself from destructive SFTP operations. Three distinct outcomes were observed:

1. **`..` traversal is BLOCKED — but by *cleaning at the virtual root*, not primarily by the containment check.** Because the request path is forced to be absolute and `path.Clean`ed *relative to the user's home*, sequences like `../../../../../../etc/passwd` collapse to a path that stays under the home dir (e.g. `.../testuser/etc/passwd`), which simply does not exist → "not found". For pure `..` payloads, the `isSubDir` "is not inside" error does **not** even fire — the cleaning neutralizes the traversal earlier.
2. **The `isSubDir` containment check *does* engage for symlink escapes, and it has a real coverage limit.** Its test is a **bare `strings.HasPrefix(sub, parent)` with no trailing-separator boundary** (`vfs/osfs.go:L285`). This blocks a symlink to `/etc` and a symlink to a *non-prefix* sibling directory — but a symlink to a **sibling directory whose absolute path shares the home dir as a string prefix** (home `.../testuser`, sibling `.../testuser-evil`) **passes** the check, allowing reads outside the home. This limit was **manifested at runtime** (a secret file in the sibling was exfiltrated). **Per the read-only scope, this is DOCUMENTED and DEMONSTRATED, not patched.**
3. **`GetRelativePath` guards the home root against destructive operations.** `OsFs.GetRelativePath` returns `"/"` exactly when a path *is* the user's home root, and the SFTP rename/rmdir/symlink handlers refuse the operation in that case (`sftpd/handler.go:L305-307`/`L322-324`/`L351-353`). At runtime, `rmdir /`, `rename /`, and `symlink /` were all denied with `Permission denied` even for a `["*"]` user (Q6c).

### Code anchors

- `vfs/osfs.go:L200-223` `ResolvePath`: reject non-absolute root (L201-203); `r := filepath.Clean(filepath.Join(fs.rootDir, sftpPath))` (L204); `filepath.EvalSymlinks(r)` (L205); if not-yet-existing → `findFirstExistingDir` walk-up (L211-215); else `isSubDir(p, fs.rootDir)` (L218); warn `Invalid path resolution, dir: %#v outside user home: %#v err: %v` (L220).

- Virtual-root cleaning for the system/hash paths — `getDestPath` forces a leading `/` then `path.Clean` (`sftpd/ssh_cmd.go:L363-366`); the SFTP layer applies the equivalent normalization before `ResolvePath`.
- Local backend gate — `IsLocalOsFs` (`vfs/vfs.go:L67`).

```go
// vfs/osfs.go:L200-223 (ResolvePath — join, clean, eval-symlinks, contain)
func (fs OsFs) ResolvePath(sftpPath string) (string, error) {
    if !filepath.IsAbs(fs.rootDir) {
        return "", fmt.Errorf("Invalid root path: %v", fs.rootDir)
    }
    r := filepath.Clean(filepath.Join(fs.rootDir, sftpPath))
    p, err := filepath.EvalSymlinks(r)
    if err != nil && !os.IsNotExist(err) {
        return "", err
    } else if os.IsNotExist(err) {
        _, err = fs.findFirstExistingDir(r, fs.rootDir)
        if err != nil {
            fsLog(fs, logger.LevelWarn, "error resolving not existent path: %#v", err)
        }
        return r, err
    }
    err = fs.isSubDir(p, fs.rootDir)
    if err != nil {
        fsLog(fs, logger.LevelWarn, "Invalid path resolution, dir: %#v outside user home: %#v err: %v", p, fs.rootDir, err)
    }
    return r, err
}
```

```go
// vfs/osfs.go:L278-291 (isSubDir — bare HasPrefix, NO trailing-separator boundary)
func (fs *OsFs) isSubDir(sub, rootPath string) error {
    parent, err := filepath.EvalSymlinks(rootPath)
    if err != nil {
        fsLog(fs, logger.LevelWarn, "invalid home dir %#v: %v", rootPath, err)
        return err
    }
    if !strings.HasPrefix(sub, parent) {
        err = fmt.Errorf("path %#v is not inside: %#v", sub, parent)
        fsLog(fs, logger.LevelWarn, "error: %v ", err)
        return err
    }
    return nil
}
```

### Q6c — `GetRelativePath` guards the home root against rename / rmdir / symlink

A distinct containment-adjacent protection is `OsFs.GetRelativePath` (`vfs/osfs.go:L183-192`), which maps an absolute filesystem path back to the user-visible virtual path. It returns `"/"` **exactly when the supplied path *is* the user's home root**: `filepath.Rel(rootDir, filepath.Clean(name))` yields `"."` for the root, which the function rewrites to `rel=""` and then returns as `"/"` (`vfs/osfs.go:L184-191`). The SFTP handlers use this to **forbid destructive operations on the home root itself** — `handleSFTPRename` (`sftpd/handler.go:L305-307`), `handleSFTPRmdir` (`L322-324`), and `handleSFTPSymlink` (`L351-353`) each guard with `if c.fs.GetRelativePath(sourcePath) == "/" { ... return sftp.ErrSSHFxPermissionDenied }`:

```go
// vfs/osfs.go:L183-192 — returns "/" exactly when name IS the user's home root
func (fs OsFs) GetRelativePath(name string) string {
    rel, err := filepath.Rel(fs.rootDir, filepath.Clean(name))
    if err != nil {
        return ""
    }
    if rel == "." || strings.HasPrefix(rel, "..") {
        rel = ""
    }
    return "/" + filepath.ToSlash(rel)
}

// sftpd/handler.go — the three home-root guards that consult GetRelativePath
func (c Connection) handleSFTPRename(sourcePath string, targetPath string, request *sftp.Request) error {
    if c.fs.GetRelativePath(sourcePath) == "/" {                    // L305
        c.Log(logger.LevelWarn, logSender, "renaming root dir is not allowed")  // L306
        return sftp.ErrSSHFxPermissionDenied                         // L307
    }
    // ...
}
func (c Connection) handleSFTPRmdir(dirPath string, request *sftp.Request) error {
    if c.fs.GetRelativePath(dirPath) == "/" {                       // L322
        c.Log(logger.LevelWarn, logSender, "removing root dir is not allowed")   // L323
        return sftp.ErrSSHFxPermissionDenied                         // L324
    }
    // ...
}
func (c Connection) handleSFTPSymlink(sourcePath string, targetPath string, request *sftp.Request) error {
    if c.fs.GetRelativePath(sourcePath) == "/" {                    // L351
        c.Log(logger.LevelWarn, logSender, "symlinking root dir is not allowed") // L352
        return sftp.ErrSSHFxPermissionDenied                         // L353
    }
    // ...
}
```
